# GliderCanyon v2：优化版滑翔场景（与 v1 并存，可对比）

v1 保留在 `GliderCanyon_Sample/` 中，没有修改；v2 是独立目录 `GliderCanyon_v2/`。
对比图见 `Renders/compare_v1_vs_v2.png`。

## 1. 实际测试环境（本说明中所有数据都来自这台机器）

| 项目 | 内容 |
|---|---|
| 场景生成、测试、渲染 | 云端 Linux 工作区：Intel Xeon 2.30 GHz 2 核、7 GB 内存、Linux 6.18；Python 3.13 + numpy/scipy；自研 C 语言 CPU 光栅渲染器（gcc 13.3）；ffmpeg 6.1 |
| 你的 Mac | Mac mini（Apple Silicon，arm64）；已确认 UE 安装在 `/Users/Shared/Epic Games/UE_5.8`（你提供的版本号为 5.8.4），Blender 在 `/Applications/Blender.app` |

这只代表软件渲染器的开销，**不能**换算成 UE 在 Mac 上的帧率。

## 2. 场景修改（对应 5 条需求）

1. **外围岩壁改为错落山脊**：
   - 高原高度改用脊状噪声生成，高度在 60–200 m 之间变化，另外加了 3 处高耸岩峰。
   - 草原边缘用大尺度噪声扭曲，并有 4 条山嘴伸进草原；中景有 3 座孤立方山。
   - 外圈有 6 个缺口通向外部（东、北、东南、南，峡谷西侧和山口北侧各一个），缺口后能看到外部草原和远山。
   - 新增两层远景地形：近景环 25 m 网格，延伸到约 3 km；远景环 250 m 网格，延伸到约 9 km，远山高 200–800 m。
2. **独立主峰**：中心 (835, 650)，峰顶 368 m。
   - 山脚：平缓的草坡，半径约 250 m。
   - 山腰：三瓣山脊构成凸形山体，有 3 层只在部分方位出现的草地平台，另有 7 处岩石突出部。
   - 山顶：偏向西南的尖顶。
   - 东北侧有一座肩部山脊。从北、东、西南三个方向看轮廓各不相同（`Renders/peak_from_*.png`）。
3. **绕山爬升航线**：
   - 出山口后向东进场，从北侧山脚开始顺时针盘旋，转过 400° 后从 64 m 爬升到 250 m，在约 47 秒越过东北肩部山脊，然后朝东南缺口外的远景飞去。
   - 盘旋半径根据山体轮廓自动计算，水平方向留出 52 m 以上余量，并做了平滑。
   - 镜头在绕山段向弯道内侧转最多 36°，让主峰占画面一侧，而不会占满。
4. **草原与岩壁**：
   - 草原：起伏幅度 ±11 m；树木分为成片树林、稀疏树木和孤树三种密度，共 2,401 棵；岩石组 55 个（每组 3–7 块，共 266 块）；草地点缀少量浅黄绿和深绿色块。
   - 岩壁：保留低多边形切面，按 9 m 一层交替使用浅橙、中橙、红棕、暗褐四档颜色，陡面和背光面颜色更深。
5. **光照与雾**：
   - 暖色阳光（仰角约 41°），柔和的蓝紫渐变天空。
   - 远景雾从 520 m 外才开始，所以飞机、光环和前方地形不受雾影响。

## 3. 交互约束与实测结果

- 玩家只控制相对航线的左右偏移（肌电输入，±12 m）。前进、沿航线转向和高度变化全部自动完成。
- 光环（9 个）是可选目标，只做重叠检测，漏过后继续沿航线飞。
- 航线全长 3,136 m，用时 58.9 s，速度 46–66 m/s；绕山段为 46–50 m/s，比峡谷段慢。

### 性能设计（面向 Mac，未实测）

- 树木和岩石全部用 HISM 实例化，共 15 个实例组；加上 3 块地形、9 个光环和飞机，场景网格绘制约 30 次（不含阴影）。
- 剔除距离：
  - 近景树：1.8–2.2 km 开始淡出（从峰顶能看到整个 1.3 km 的游玩区）。
  - 岩石：0.9–1.2 km。
  - 远景树簇：只用 18 面的低模，6.5–8 km 剔除，不投射阴影。
- 近景树由 UE 自动生成 LOD1（面数 25%）和 LOD2（面数 8%）。远景地形用 250 m 网格。整张场景只用一张 256×256 的调色板贴图。
- `run_perf_test.command` 会在 1920×1080 下分别跑两档画质，每档先跑一遍不计数的预热，再完整播放一遍飞行序列并用 UE 的 CSV 性能分析器记录：
  - **High**：Lumen + 虚拟阴影贴图。
  - **Performance**：关闭 Lumen、使用普通阴影、75% 渲染分辨率。
  
  结果输出到 `PerfResults/`：平均 FPS、p95/p99 帧时间、1% 低帧、超过 33 ms 的卡顿次数，以及游戏线程、渲染线程和 GPU 耗时。

## 4. 项目路径与使用方法

建议把整个目录放到 `~/Documents/GliderCanyon_UE58/GliderCanyon_v2/`（新目录，不碰现有项目）：

```
GliderCanyon_v2/
├─ build_all.command          ① Blender 生成 .blend 和 FBX → ② UE 5.8 打开项目并自动建关卡
├─ run_perf_test.command      ③ 在本机实测两档画质的帧率
├─ UE/GliderCanyonV2/         UE 5.8 纯蓝图项目（.uproject + Config），脚本把内容生成到 /Game/GliderCanyon_v2/
├─ Blender/                   （运行后生成）GliderCanyon_v2.blend 源文件
├─ FBX/                       （运行后生成）每个地形层和原型一份 FBX
├─ GliderCanyon_v2_Scene.glb  整个场景，树木和岩石是共享网格的实例节点
├─ Meshes_GLB/ Meshes_OBJ/    3 层地形、起点台、航线引导、8 个树木原型、4 个岩石原型、光环、占位飞机
├─ Textures/                  T_LowPolyPalette_v2.png
├─ Data/                      Instances_UE.csv（3,577 个实例，含 UE 坐标与剔除距离）、
│                             FlightSpline_v2.json 和逐米采样 CSV（含时间、速度、坡度、分区）、
│                             Flythrough_Track_UE.csv（飞机和镜头轨迹）、测试报告
├─ Renders/                   4 个指定视角（带/不带 HUD）、主峰三向视图、俯视图、总览、v1/v2 对比图、两段视频
└─ Generator/                 v2 生成器源码（Python + C）
```

**素材来源**：全部由本项目代码程序化生成，没有使用任何第三方模型、贴图、扫描数据或商店资产。字体（思源黑体 / Noto Sans CJK）只用于渲染图上的 HUD 文字。

## 5. 已知限制

- **UE 和 Blender 脚本未经实测**（按 UE 5.x 和 Blender 4.x 的 Python API 编写，只做过语法检查），Mac 帧率也没有测。首次运行如果报错，把 `UE/GliderCanyonV2/Saved/Logs/*.log` 发给我即可修。
- 包里没有 `.uasset`、`.umap` 和 `.blend` 成品，需要在你的 Mac 上运行 `build_all.command` 生成。
- 截图和视频来自 CPU 软件渲染器：没有全局光照，阴影较硬。UE 的 Lumen 和天空大气效果会有差别，颜色需要在 UE 里微调。
- 山口段沿用 v1 的峡谷线形，垂直加速度 0.47 g，比绕山段明显；如需更柔和，可以下调山口控制点。
- 地形是高度场，岩石突出部是单独的实例模型。
- 草地是平面着色，没有草叶效果，可以后续在 UE 里用 PCG 或 Grass 按距离分级加上。
- 第 3 个视角（山腰爬升）中主峰约占画面右侧 20%，这是为了"不占满画面"做的取舍。如果希望山体更有压迫感，把 `render.py` 里的 `amax` 从 36° 调大即可。
